## Implementation Strategy for `main.py`

### Section 1 — Imports & Constants
```python
MODEL_ID = "Qwen/Qwen2.5-1.5B-Instruct"
TARGET_CONTEXT_TOKENS = 6000
MAX_MODEL_LEN = 8192
GPU_UTIL = 0.85
MAX_NEW_TOKENS = 1          # max_tokens=1 for cleanest TTFT measurement
TTFT_HIT_THRESHOLD = 0.5   # seconds
```

### Section 2 — `generate_context(target_tokens) -> str`
- Define a ~74-token financial policy paragraph (deterministic, no randomness)
- Repeat it `ceil(target_tokens / para_tokens)` times
- Verify with `tiktoken.get_encoding("cl100k_base")`
- **Critical**: context must be byte-identical across all 3 runs for APC to work

### Section 3 — `make_table(rows_data) -> Table`
- Returns a freshly-built `rich.table.Table` from a `rows_data: list[tuple]`
- 4 columns: Run | Scenario | TTFT (s) | Cache Status
- Called on every `live.update()` call (Rich tables are immutable once rendered)

### Section 4 — `measure_ttft(llm, prompt) -> float`
```python
sampling = SamplingParams(max_tokens=1, temperature=0.0)
t0 = time.perf_counter()
llm.generate([prompt], sampling_params=sampling)
return time.perf_counter() - t0
```

### Section 5 — `run_experiment(llm, context, live, rows_data)`
Three runs with specific prompt structures:

**Run 1 — Cold Cache (MISS)**
```
[SYSTEM: Financial Policy Assistant]
{6000-token context}

User ID: USR-<uuid1>
Question: What is the maximum expense without prior approval?
```
→ Dynamic vars at BOTTOM. First inference, cache cold. Expected: ~2.5–4s

**Run 2 — Hot Cache (HIT)**
```
[SYSTEM: Financial Policy Assistant]
{same 6000-token context}          ← identical prefix to Run 1

User ID: USR-<uuid2>               ← different UUID but still at BOTTOM
Question: Can I submit receipts after 45 days?
```
→ Prefix hash matches Run 1 up to ~6020 tokens. APC reuses KV cache. Expected: <0.2s

**Run 3 — Cache Destroyed (MISS)**
```
User ID: USR-<uuid3>               ← moved to TOP — breaks prefix at token 1

[SYSTEM: Financial Policy Assistant]
{same 6000-token context}

Question: How many days to submit an expense report?
```
→ Token 1 changed → entire 6000-token cache invalidated. Expected: ~2.5–4s

For each run:
1. Append `("Running...", dim style)` placeholder row → `live.update(make_table(rows_data))`
2. Call `measure_ttft()`
3. Replace last row with final result (TTFT + colored HIT/MISS)
4. `live.update(make_table(rows_data))`

### Section 6 — `main()`
```python
llm = LLM(
    model=MODEL_ID,
    enable_prefix_caching=True,
    max_model_len=MAX_MODEL_LEN,
    gpu_memory_utilization=GPU_UTIL,
    dtype="float16",          # Required: T4 has no bfloat16 hardware support
    trust_remote_code=True,
    tensor_parallel_size=1,
)
```

## Critical Gotchas

1. **`dtype="float16"` is mandatory** — T4 GPU (sm_75) has no bfloat16 support; `dtype="auto"` may crash
2. **Model name**: PRD's `Qwen/Qwen3.5-1.5B-Instruct` returns 404 on HuggingFace — use `Qwen/Qwen2.5-1.5B-Instruct`
3. **APC requires byte-identical prefix** — same `context` Python variable across all 3 runs; no randomness in context body
4. **Rich tables are immutable** — must rebuild `Table` from `rows_data` list on each `live.update()` call
5. **vLLM init is slow** — ~30–60s on warm boot, 2–5 min on first model download

## GPU Migration: T4 → L4 (Required Fix)

**Problem**: Triton 3.3.0 has a regression bug compiling vLLM's `prefix_prefill.py::_fwd_kernel` for sm_75 (T4/Turing). Multiple workarounds were attempted (enforce_eager, chunked_prefill, IN_PRECISION patch) — all failed because the bug is in Triton's LLVM NVPTX backend for sm_75 itself.

**Solution**: Switch runtime to L4 GPU (sm_89, Ada Lovelace):
- Triton 3.x works correctly on sm_89
- vLLM V1 engine becomes available
- FlashAttention-2 supported natively
- bfloat16 supported natively (can use `dtype="auto"`)
- 24 GB VRAM (more headroom than T4's 16 GB)
